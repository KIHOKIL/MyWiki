🏷️ 설계 ①: 모르면 모른다고 표시한다 (#23)

  • stale: 인덱스 커밋 이후 바뀐 파일 표시 ➔ brain build . --if-stale

● PART 4-A · WHY SKILL EVAL MATTERS

Eval이 잡은 2026년 숫자 세 개 & pass@3 vs pass^3

스킬에도 테스트 코드가 필요하다: 감(Vibe)이 아니라 통계적 신뢰구간과 작업 성격에 맞는 지표로 판단

📊 1. 2026년 업계 실측 숫자 세 개 (#34)

  • 56% — 스킬이 아예 안 불린 케이스 (Vercel, Next.js 16 eval, 2026-01)
  • 6개 중 5개 — Eval로 description을 고쳐 트리거가 개선된 스킬 (Anthropic, 2026-03)
  • -44% — 스킬로 줄인 비용, 단 완전성 Eval이 빠진 답을 잡음 (Arize, 2026-07)

🎲 2. pass@3 vs pass^3 (#39, τ-bench)

  • 10번 중 8번(80%) 맞히는 에이전트를 같은 문제에 3번 돌릴 때:
  • pass@3 (한 번이라도 맞으면 OK = 99.2%): 버그 수정 패치 하나 건지기
  • pass^3 (매번 맞아야 OK = 51.2%): 깨질 파일 전수 조사 (한 번 빠뜨리면 장애)

🎯 3. "전부 찾아라" 채점: Recall & Precision (#42)

  • 코드 파일 4,488개 전부 다 찍기 ➔ Recall 1.00 / Precision 0.09 (실패)
  • 첫 묶음 50개만 내고 끝내기 ➔ Recall 0.13 / Precision 1.00 (실패)
  • 통과선(실행 전 FROZEN.json 고정): Recall ≥ 0.9 AND Precision ≥ 0.8 동시 충족

🧪 4. 비교군 4개 설계 (suite.yaml, #40)

  • none (스킬 없음) vs v1 (스킬 적용) ➔ Uplift 측정
  • v1 vs v2 (규칙 한 줄 수정 패치) ➔ Regression 측정
  • v1 vs v1b (바이트 단위 동일 복사본 A/A) ➔ 하네스 자체 흔들림 확인
● PART 4-B · GRADING ARCHITECTURE (skill_eval/checks.py)

채점 코드: 게이트(Hard Check) 먼저, Judge는 그다음

"0점에도 이름이 있다" — 무결성 위반(invalid), 안전 위반(safety_violation), 오답(fail)의 엄격한 분리

1. 게이트 우선 판정 (#38, #43)

  • integrity 위반 (정답 엿보기): 0점이 아니라 outcome: "invalid"(score: None)로 모수에서 제외!
  • safety 위반 (저장소 변경): git status/HEAD 변동 시 즉시 0.0점
  • correctness 실패: 인용 파일/줄 번호 허위(cites_exist) 또는 Recall/Precision 미달 시 즉시 0.0점

2. Judge 3표 다수결 (#38)

  • 모든 하드 체크 게이트를 통과한 trial만 Judge 호출
  • 에이전트(Sonnet)와 다른 상위 모델(Opus)을 도구 없이 격리 호출
  • 루브릭 10항목 각각에 대해 Judge 3명(3회) 다수결 투표로 PASS/FAIL 결정 (통과선 0.7)

3. 채점기 자체 검증 (#45)

  • skill-eval selftest ($0): 채점 코드 자체의 단위 테스트 선행
  • skill-eval keycheck ($0): 정답 파일이 실제 커밋/줄 번호를 가리키는지 검증
  • skill-eval freeze: 케이스·정답·채점기 SHA256을 FROZEN.json에 박제해야 실행 가능
● PART 4-C · SANDBOX ISOLATION (skill_eval/isolation.py)

Eval 프로세스 4대 차단 원칙: 데이터 오염 및 보상 해킹 방지

테스트 대상 스킬의 순수 기여도(Delta)만 객관적으로 검증하기 위한 4대 격리와 21개 프로브(probe 21/21 PASS)

🚫 1. 원본 Repo 차단 (개발 소스 & 메타데이터 격리)

  • 반칙(Cheating): git log/diff나 초안을 뒤져 문제 출제 의도 파악
  • 효과: 컨닝 페이퍼 차단 및 실제 패키지 배포 환경 100% 모사
  • 구현: 매 trial마다 $TMPDIR APFS clone 생성, origin 제거, .claude/.agents sparse strip 및 원본 경로 deny

🔒 2. 정답 차단 (Golden Patch 은닉 & 역설계 방지)

  • 반칙(Reward Hacking): find/grep으로 answer-keys나 채점 코드 베끼기
  • 효과: 채점 통과 조건만 하드코딩하는 역설계(Reverse Engineering) 원천 차단
  • 구현: 워크스페이스 외부 격리 + permissions.deny + 적발 시 0점이 아닌 outcome: invalid(무효) 처리

🧹 3. ~/.claude 차단 (글로벌 환경 & 개인화 격리)

  • 반칙(Contamination): 전역 CLAUDE.md, 개인 스킬, MCP, 자동 메모리에 의존
  • 효과: 스킬 적용 전(none) vs 후(v1)의 순수 기여도(Delta)만 변인 통제
  • 구현: 매 trial 빈 CLAUDE_CONFIG_DIR + 번들 스킬 22종 off + disableAllHooks + 상위 폴더 검사

🌐 4. 네트워크 차단 (외부 의존성 차단 & 결정론적 평가)

  • 반칙(Bypass): 막히는 부분을 구글링하거나 외부 패키지 설치로 우회
  • 효과: 시간에 따라 변하는 외부 웹 상태를 배제해 결정론적 재현성(Determinism) 확보
  • 구현: OS 커널 샌드박스(sandbox.enabled: True, allowUnsandboxedCommands: False) + probe 21/21 검증
● PART 5 · MATURITY MODEL (L0 ~ L5) & SCORECARD

팀은 6단계로 올라간다 (L0 ~ L5) & Skill Eval 대시보드

가장 큰 점프는 L3 ➔ L4 ("누가 돌려야 확인" ➔ "고칠 때마다 저절로"), 가장 중요한 단계는 L5 (운영 실패의 회귀 케이스화)

📈 메타의 Eval 성숙도 6단계 (#48)

  • L0 ~ L2: 느낌(Vibe) ➔ 하드 체크 ➔ 일회성 수동 비교
  • L3 (세미나 단계 · judge + k번 + 기준선): 루브릭 채점 · k=3 반복 · 스킬 없음(none)과 비교해 "도움이 됐다"를 숫자로 증명
  • L4 (가장 큰 점프 · 고칠 때마다 CI): SKILL.md를 고치는 PR마다 Eval이 자동 실행되어 Merge 전 빨간불 차단
  • L5 (가장 중요 · 운영 실패 ➔ 새 케이스): 실제로 틀린 장면을 케이스로 추가해 같은 실수를 두 번 안 하는 회귀 루프 완성

📊 Skill Eval 점수판 대시보드 해석법 (#51)

  • AutoKliq 300/300 trials 실측 ($65.61): 격리 OK · 제외 0 · 권한 거부 0 · 토큰 +18%
  • 통과율: 스킬 없음(none) 88% ➔ v1 93% ➔ v2 95% ➔ v1b(A/A) 93%
  • 95% 신뢰구간(CI) 막대 해석: 케이스별로 짝지은 차이(Paired Δ)의 95% 구간 막대가 0 선에 걸치면 "차이를 확신할 수 없다(검출 불가)"로 정직하게 판정!
