AI 에이전트를 위한
2nd Brain과 Eval 프레임워크

Meta 8년차 시니어 엔지니어가 밝히는 자율 에이전트 구축의 두 기둥: 맥락(Context)과 검증(Verification)

⌨️ 키보드 좌우 화살표 (← / →) 로 슬라이드를 넘길 수 있습니다
Part 1 · The Real Bottleneck

AI 코딩의 병목은 '작성'이 아닌 '검증'

프롬프트를 깎지 말고, 컨텍스트와 검증을 관장하는 시스템 하네스를 만들어야 합니다.

❌ 과거 vs 현재의 병목

  • 과거: 코드 타이핑과 구현 속도가 병목
  • 현재: 초당 수백 줄의 코드가 쏟아져 나와 리뷰와 검증이 극한의 병목
  • 환각(Hallucination)에 대한 불안으로 인간 피로도 증가

🛡️ 하네스(Harness) 전환

  • 에이전트에게 매번 설명을 반복하는 것은 시스템 실패
  • 지식 레이어(2nd Brain)가 맥락을 자동으로 공급
  • 검증 레이어(Eval)가 통계적 신뢰성을 자동으로 증명
Part 2 · Developer's 2nd Brain

개발자용 세컨드 브레인의 2대 기둥

코드베이스 지도와 의사결정 역사가 결합될 때 비로소 에이전트 온보딩이 완성됩니다.

🕸️ 기둥 1: Codebase Graph

  • 컴파일러 AST 기반의 결정론적 심볼 그래프
  • 단순 검색이나 벡터 RAG를 압도하는 정확도
  • $k$-Hop 그래프를 통해 변경 시 파급 반경(Blast Radius) 자동 계산

🧠 기둥 2: Code Memory

  • 코드 자체에는 없는 "왜 이렇게 구현했는가?"(Why)
  • 과거 장애 회고, 아키텍처 결정(ADR) 문서
  • 에이전트가 신임 시니어 개발자처럼 프로젝트 배경 이해
Part 3 · Verification & Eval

Eval: 에이전트 품질을 증명하는 정량적 검증

테스트 코드 없이 배포하지 않듯, Eval 없는 에이전트 스킬은 쓸 수 없습니다.

⚖️ Eval-Driven Development (EDD) 3대 검증 기준

  • Trigger Accuracy: 스킬과 에이전트가 필요한 순간에만 정확히 발동하는가?
  • Quality Gain: 기존 대비 성능과 검출율이 정량적으로 향상되었는가?
  • Zero Regression: 새로운 규칙이 다른 정상 코드를 오탐(False Positive)으로 차단하지 않는가?
  • CI/CD 자동 결합: GitHub Actions PR 머지 단계에서 자동으로 다수결 판정 수행
