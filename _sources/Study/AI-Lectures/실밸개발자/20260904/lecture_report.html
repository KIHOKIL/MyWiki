에이전트 시대의 터미널 Herdr

메타 시니어 엔지니어가 잘때도 에이전트를 돌리는 법

1. Executive Summary

과거에는 tmux가 개발자의 화면 분할 및 백그라운드 세션 유지를 위해 쓰였다면, 이제는 여러 개의 코딩 에이전트(예: Claude Code, Codex 등)를 동시에 띄워놓고 작업을 지시하는 '다중 에이전트 오케스트레이션' 시대입니다.

에이전트를 여러 개 띄우다 보면, 어떤 에이전트가 승인을 기다리고 있고 어떤 에이전트가 작업 중인지 파악하기 힘들어 '병목은 인간'이 되는 현상이 발생합니다. Herdr는 에이전트의 상태(Working, Blocked, Done)를 실시간으로 인식하고 알림을 주는 오픈소스 멀티플렉서입니다.

2. 터미널 멀티플렉서의 귀환과 한계

서버-클라이언트 구조

터미널 앱, 서버, 프로세스의 3층 구조로, 터미널 앱을 닫아도 서버에서 에이전트는 계속 동작합니다.

tmux의 부활

프로세스가 "내가 보지 않는 동안 오래 도는 것"으로 성격이 바뀌면서 tmux의 세션 유지 기능이 필수불가결해졌습니다.

기존의 치명적 한계

pane 안에서 뭐가 도는지 모릅니다. 에이전트가 에러로 멈춰서 "승인 대기(Blocked)" 상태여도 사용자가 보지 않으면 멈춰 있습니다.

3. Herdr: 에이전트를 아는 터미널 (3가지 차별점)

  • 에이전트 상태 인식 (5 States): 사이드바를 통해 Blocked, Working, Done, Idle, Unknown 상태를 직관적으로 표시합니다.
  • 에이전트 주도 조작: 에이전트가 명령 한 줄로 Herdr의 탭과 Pane을 스스로 쪼개고 조작할 수 있습니다.
  • 세션 및 대화 복원력: 터미널이나 서버를 닫았다 켜도 claude --resume 등을 통해 에이전트 대화 맥락이 온전히 복원됩니다.

4. 실무 파이프라인 (AutoKliq 개발 데모)

한 Claude Code(오케스트레이터)에게 지시하면, 해당 에이전트가 herdr 스킬을 사용하여 직접 worktree를 파고 새로운 pane을 3개 띄워 서브 에이전트들을 기동합니다.

# 에이전트가 herdr를 다루는 스킬 명령 (예시)
herdr split-pane --horizontal
herdr send-keys -t 1 "claude --resume" Enter

5. Agentic Analysis (도구 비교)

Herdr vs Warp / Conductor

Warp나 Conductor는 모던 터미널 기반 통합 도구지만, "터미널을 끄면 에이전트도 죽는가?"라는 질문에 Herdr는 백그라운드 서버 아키텍처로 완전한 생존을 보장합니다.

인간 UI vs 가상 OS

Herdr는 인간을 위한 UI가 아니라, 에이전트가 살아가고 스스로 화면을 통제하는 '가상 런타임(Runtime)'이라는 철학적 전환을 꾀했습니다.
