Slide 02 / 08 · Cumulative Defense (Video p.119)

두 갈래 리뷰 시점: Pre-PR과 Post-PR은 누적된다

앞단(Pre-PR)에서 기본 결함을 다 잡아야 뒷단(Post-PR)이 무거운 아키텍처·리스크 분석에 집중할 수 있다.

1. PRE-PR REVIEW (로컬 .githooks/pre-push)

  • 시점: git push 직전 (commit마다 돌면 느려서 push 직전으로 피벗)
  • 동작: 헤드리스 CLI (claude -p / opencode run)
  • 판정: 마지막 줄 VERDICT: FAIL 시 exit 1로 푸시 차단

2. POST-PR REVIEW (GitHub Actions CI)

  • 시점: PR 생성 및 새 커밋 푸시 시 자동 실행
  • 동작: 이종 모델 API 호출 + 5축 리스크 점수(0~100) 산출
  • 결과: 단일 마커 코멘트(<!-- ai-pr-review -->) Upsert 및 라벨 부착

Slide 06 / 08 · Multi-Agent & Cross-Model Review (Video p.124)

이종 모델 크로스 리뷰(Cross-Review) & 멀티 에이전트

코드를 작성한 모델과 같은 모델로 리뷰하면 '자기 확증 편향(Self-Bias)'이 발생한다.

강의 원형: Claude ↔ Codex(GPT) 교차

  • 로컬 코딩이 Claude면 CI 리뷰는 GPT API로 수행
  • 36점 미만 소형 PR은 단일 패스(/code-review)
  • 36점 이상 고위험 PR은 병렬 서브에이전트 + 메타 디듀플리케이션(ultrareview)

PHY SW 그룹: OpenCode + Open-Weight LLM 교차

  • 작성 모델: Qwen3-Coder 또는 GLM-4.5
  • 리뷰/검증 모델: DeepSeek-R1 / DeepSeek-V3
  • OpenCode의 서브에이전트 기능으로 ISR · HAL · IPC/3GPP 병렬 심사 후 Chief Verifier가 오탐 기각

Slide 07 / 08 · 6 Safety Guards (Video p.125)

도입 전 6대 안전 가드 — 메인 Repo에 바로 켜지 마세요

Step 1 ~ 3: 조직 합의와 보수적 출발

  • 01. 팀 동의 먼저: 개인 설정이 아닌 그룹 공식 프로세스로 합의
  • 02. 저위험 PR부터: 문서(.md), 빌드 스크립트, 주석 PR부터 시작
  • 03. 보수적 임계치: 초기엔 모든 PR을 risk:medium 이상으로 취급해 데이터 축적

Step 4 ~ 6: 다중 차단막과 Dry-Run

  • 04. 라벨·작성자 화이트리스트: auto-merge-ok 라벨 및 지정 작성자 한정
  • 05. 야간·주말 금지: 평일 10시~17시 외에는 자동 머지 원천 비활성
  • 06. 첫 1~2주 Dry-Run: 코멘트와 점수만 달고 차단/머지는 수행하지 않음
6 Safety Guards Before Production Rollout
