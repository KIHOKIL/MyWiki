AI 시대의 새로운 패러다임: Spec-Driven Development

실밸개발자 (메타 시니어 엔지니어 하재상) 강의 전수 요약 & 엔지니어링 분석

🌟 Executive Summary: 스펙이 구현을 주도하는 시대

AI 시대에 코딩의 단가와 소요 시간은 사실상 0으로 수렴하고 있습니다. 과거에는 100명의 개발자를 채용하여 코딩과 테스트 병목을 해소하려 했지만, 이제는 설계(Design)와 검토(Review)가 유일한 엔지니어링 병목입니다.

TDD(Test-Driven Development)는 무엇을 만들지가 명확한 함수나 버그 수정에는 유용하지만, 새로운 도메인이나 아키텍처를 맨 처음 정의할 때는 테스트를 먼저 작성하기 어렵습니다. SDD(Spec-Driven Development)는 인간이 자연어 스펙을 정밀하게 다듬고, AI가 계획 수립, 격리된 서브세션 코딩, 자가 교정까지 완결 짓도록 지휘하는 AI-Native 개발 방법론입니다.

🧠 SDD를 위한 5대 사고방식 전환 (Mindset Shift)

1. Spec First, Code Second

코드 전에 자연어 스펙 작성. 명확한 스펙은 단번에 프로덕션 코드로 직행함.

2. Reviewer, Not Author

인간은 타이핑하는 코더가 아닌 아키텍처와 엣지케이스를 판정하는 리뷰어.

3. Externalize Mental Context

머릿속 암묵지를 CLAUDE.md 및 ADR로 외부화. 적히지 않은 지식은 AI가 모름.

4. Attention on Design Bottleneck

주의력의 80%를 스펙 설계에 투입. 설계가 가장 높은 레버리지 구간.

5. Closed Learning Loop (복리 성장)

AI 실패를 규칙으로 환류하여 시스템을 개선. 50번째 세션은 첫 번째 세션보다 압도적으로 생산적이어야 함.

🔄 SDD 5단계 라이프사이클 루프

단계 주체 핵심 활동 산출물
1. 설계 (Design) 인간 주도 목표, 아키텍처, 결정 이유(ADR), 제약 사항 정의 PRD.md, ARCHITECTURE.md, ADR.md
2. 계획 (Plan) AI 주도 / 인간 승인 스펙을 자기완결적 Step 단위로 분할 phases/index.json, step{N}.md
3. 구현 (Execute) AI 자율 독립 헤드리스 세션에서 컴파일 및 AC 테스트 자율 통과 프로덕션 코드, 단위 테스트
4. 교정 (Correct) 인간 주도 유저 저니, 에러 매트릭스 검토 및 피드백 주입 재계획 및 보강된 스펙
5. 회고 (Reflect) 인간 주도 반성문에서 도출된 교훈을 규칙으로 영구 승격 CLAUDE.md 가드레일 업데이트

🛡️ claude -p 헤드리스 모드 & 컨텍스트 오염 차폐

메인 컨텍스트가 커지면 발생하는 재앙

단일 대화 세션에서 5개 이상의 Step을 연속 구현하면 컨텍스트 윈도우가 150k를 초과하여 모델 지능이 30% 수준으로 폭락합니다. 하네스 프레임워크의 execute.py는 각 Step을 독립된 1회용 서브프로세스로 분리 실행하여 이를 해결합니다. 

# scripts/execute.py의 핵심 격리 로직
def _invoke_claude(self, step: dict, preamble: str) -> dict:
    step_num, step_name = step["step"], step["name"]
    step_file = self._phase_dir / f"step{step_num}.md"
    prompt = preamble + step_file.read_text()
    
    # claude -p 헤드리스 모드로 1회성 서브세션 실행 (메인 세션 오염 없음)
    result = subprocess.run(
        ["claude", "-p", "--dangerously-skip-permissions", "--output-format", "json", prompt],
        cwd=self._root, capture_output=True, text=True, timeout=1800,
    )
    return output

[Prompt 1] 썸네일 생성기 의도 제시 및 스펙 수립 요청

오늘 나는 유튜브 썸네일을 GPT-Image-2 API를 사용해서 만드는 서비스를 만들어 볼 거야.
이 서비스는 사용자의 브리프(프롬프트)와 선택적인 이미지를 입력받아서 유튜브 16:9 썸네일 이미지를 생성하는 웹 애플리케이션이야.
- 인풋: 프롬프트(필수), 참조 이미지(선택)
- 아웃풋: 16:9 썸네일 이미지 (후보 2개 동시 생성)
- 타겟 사용자: 유튜브 크리에이터
- 목적: 썸네일 제작 시간을 단축하고 고품질 썸네일을 쉽게 제작하여 시청자 유입률 증대
현재 저장소의 구조를 파악하고, docs/ 하위 문서(PRD, ARCHITECTURE, ADR, CLAUDE.md)를 바탕으로 스펙과 구현 계획(Plan)을 수립해 줘.

[Prompt 2] 스펙 고도화 (티키타카 - 유저 저니 & 에러 매트릭스 보강)

플랜이 아주 빈약해. 특히 유저 플로우(User Journey)와 에러 핸들링 매트릭스를 잘 설계해 줘야 돼.
사용자가 어떻게 진입해서 어떤 폼을 작성하고, 검증 실패 시 어떻게 처리되며, API 호출 실패나 에러가 발생했을 때 조건부 재시도 및 UI 피드백을 어떻게 줄 것인지 다이어그램과 표로 아주 디테일하게 보강해 줘.
그리고 MVP 목적에 맞게 오버엔지니어링은 하지 말고, 최소한의 변화로 최대의 아웃풋을 내도록 계획을 다시 짜 줘.

[Prompt 3] `/harness` 슬래시 커맨드 실행

/harness
docs/ 하위 문서(PRD, ARCHITECTURE, ADR, CLAUDE.md) 작성을 완료하고, 각 Step이 독립된 세션에서 실행될 수 있도록 Scope 최소화, 자기완결성, AC 실행 커맨드를 포함한 phases/0-mvp/index.json 및 step0.md ~ step4.md 파일들을 생성해 줘.

🏢 그룹장 도메인 최적화: 임베디드 SW & 통신 프로토콜 적용

1. HW 레지스터 맵 기반 C/C++ 임베디드 하네스

신규 Baseband / RFIC 레지스터 맵 명세서(오프셋, 비트필드, 권한)를 docs/PRD.md에 정의하고, execute.py를 통해 C 구조체 헤더 정의 ➡️ 비트 조작 인라인 함수 ➡️ QEMU/호스트 단위 시뮬레이션 AC(Acceptance Criteria) 검증까지 자동화.

2. 계층형 스펙(Hierarchical Specs)을 통한 3GPP 프로토콜 분할 정복

대규모 3GPP 릴리즈 규격을 단일 프롬프트에 넣지 않고, Master Spec 아래 L1 PHY(디코딩), L2 MAC(HARQ 제어), L3 RRC(상태 머신)로 모듈화하여 각 계층별 독립 step.md로 무환각 구현.

3. JIRA / 필드 이슈 분석 자동 회고 루프

통신 필드 Drop call 또는 타이밍 이슈 분석 결과를 docs/ADR.md 및 CLAUDE.md의 CRITICAL 규칙으로 영구 승격하여, 다음 개발 시 동일한 버그가 원천 방지되도록 시스템 자산화.
