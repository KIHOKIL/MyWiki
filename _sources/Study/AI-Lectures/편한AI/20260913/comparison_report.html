로컬 가이드 vs OpenHuman vs Claude-Obsidian 의 아키텍처 및 철학 비교

1. 개요 및 설계 철학

Andrej Karpathy가 제시한 "LLM 기반의 자가 조직 위키" 개념을 바탕으로 구현된 3가지 대표적인 접근 방식을 분석합니다.

Local Guide (기본형)

철학: 투명하고 직관적인 파이썬 스크립트 기반 자동화.

  • Antigravity IDE 연동
  • 가장 직관적인 구조
  • 완전한 사용자 통제권

OpenHuman

철학: 옵시디언을 뇌로 쓰는 거대 자율 에이전트 플랫폼.

  • TokenJuice 압축 기술
  • 100+ 외부 앱 Auto-fetch
  • tinyflows/tinyagents 엔진

Claude-Obsidian

철학: 철저한 데이터 무결성과 안전한 트랜잭션.

  • 롤백(Rollback) 지원
  • 원본 출처 엄격 보존
  • 클레임 린팅(Linting) 검증

2. 핵심 기능 상세 비교표

기능 / 도구 Local Guide OpenHuman Claude-Obsidian
타겟 유저 일반 파이썬 사용자 자동화 만능주의자 학구적 지식 관리자
자동화 수준 반자동 (명령어 트리거) 완전 자율 (백그라운드 갱신) 승인 기반 (결정론적)
외부 연동 Web Clipper 의존 방대한 생태계 직결 로컬 파일 중심
안정성 설계 직접 수정 (백업 권장) 샌드박스 지원 원자적 트랜잭션 롤백

3. Next Action: 사내 도입 제언

우리 조직(C/C++ 레거시 리팩토링 및 통신 프로토콜 그룹)의 특수성을 고려할 때, 다음의 하이브리드 접근을 권장합니다.

  • 보안 및 무결성: 기밀 문서를 다루므로 Claude-Obsidian의 트랜잭션 롤백 모델과 엄격한 출처 린팅 파이프라인 도입이 1순위입니다.
  • 정보 수집 체계: Jira나 Confluence 이슈를 자동으로 긁어모으는 OpenHuman의 Auto-fetch 메커니즘을 결합하여 지식 최신화를 보장합니다.
  • 데이터 격리: 외부 LLM 서버로 소스 코드가 유출되지 않도록, Sandbox 환경을 연계하고 필요시 로컬 모델(Ollama 등) 라우팅을 혼합 적용합니다.
