# LLM Wiki 툴 비교 및 도입 가이드

최근 생성형 AI와 노트 테이킹 앱이 결합된 형태의 지식 베이스가 주목받고 있습니다. 단순 검색형인 [[llm-wiki-vs-rag|RAG 시스템과 달리 LLM Wiki]]는 지식을 영구적으로 구조화하고 저장할 수 있습니다. 

사용 환경(보안 수준, 필요 리소스, 자동화 여부)에 따라 추천되는 시스템이 달라지며, 주요 도구들의 비교 분석은 다음과 같습니다.

## 1. 개인용 (빠른 도입)

별도의 서버 구축 없이 기존 노트 앱에서 바로 구동하고 싶을 때 유용합니다.

- **대표 도구:** [[obsidian-llm-plugins|Smart Connections, Copilot for Obsidian]]
- **장점:** 
  - 세팅이 가장 쉽고 빠릅니다.
  - 내 로컬 컴퓨터의 리소스를 사용하거나 API 비용만 지출하면 됩니다.
- **단점:** 
  - PC 성능이나 API 호출에 한계가 있으며, 대규모 문서 처리나 백그라운드 자율 에이전트 동작은 지원하기 어렵습니다.

## 2. 개인 고도화 및 소규모 팀용

나만의 지식 베이스를 자율적으로 정리해주는 수준 높은 위키 모드가 필요할 때 추천합니다.

- **대표 도구:** [[weknora|WeKnora]] (Tencent 오픈소스)
- **장점:**
  - **Wiki Mode:** AI가 단순히 문서를 읽어주는 것에 그치지 않고, 알아서 문서를 마크다운으로 변환, 요약하고 하이퍼링크를 연결해 줍니다.
  - 지식 베이스가 스스로 성장하는 느낌을 줍니다.
- **단점:**
  - 서버(또는 로컬 컨테이너) 구축 및 운영 지식이 필요합니다.

## 3. 엔터프라이즈 및 사내 지식 관리 (보안 중심)

사내 기밀 데이터가 외부 클라우드(OpenAI 등)로 나가는 것을 엄격히 차단해야 하는 환경에 적합합니다.

- **대표 도구:** [[xwiki|xWiki]], 온프레미스 구축형 LLM (Qwen, GLM 등 연결)
- **장점:** 
  - **BYO-LLM (Bring-Your-Own-LLM):** 회사 내부에 설치된 승인된 LLM만 연결하여, 사내 데이터 유출을 원천 차단합니다.
  - 강력한 권한 관리 및 기업용 위키 기능이 탑재되어 있습니다.
- **단점:**
  - 도입 비용과 사내 인프라 관리 비용이 가장 높습니다.

---

## 기타 프레임워크 접근법
LLM을 얹어 지식 그래프를 구성하는 개발 프레임워크 관점의 접근도 있습니다.
- **LlamaIndex, LightRAG, GraphRAG:** 개발자가 사내 환경에 맞춰 LLM 파이프라인과 RAG/Wiki 형태를 직접 커스텀 구현할 때 뼈대가 되는 기술입니다.

## 요약 (추천 가이드)
- **내가 쓰기 편하게 (집):** Obsidian + `Smart Connections`
- **지식 정리를 AI에게 맡기고 싶을 때:** `WeKnora`
- **회사 사내망에서 구축해야 할 때:** `xWiki` + `사내 로컬 LLM`
